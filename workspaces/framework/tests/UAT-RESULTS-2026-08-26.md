**Result:** `Unassigned` handled cleanly — no error, no spurious view, no attempt to create an `Unassigned` workspace folder. Gazoo appears in **no** generated view (grep: 0 hits), confirming the UAT-12 master-view gap: an unassigned person is visible only in the registry folder. (`widget/CONTACTS.md` was already removed in the 0.4.1 re-run, so only `bd-sow-001` regenerates; the `ghost-ws` warning persists as expected.)

**Finding (BUG-212) — placeholder tokens leave no valid resting state.** `fw-new-contact.sh` seeds the record with `__ORG__`, `__EMAIL__`, `__ROLE_OR_TITLE__` etc., but the template forbids placeholders surviving. So between "created" and "fully filled" there is no legal state, and an interrupted add (the normal case — often all you have at first is a name) leaves a record that is indistinguishable on disk from a botched fill. The blank-field convention from BUG-207 already covers "not known yet" and is greppable. **Fix:** the create gate should emit empty `**Field:**` lines, with the guidance in the command or in a comment header the script strips — never in the values. Required-vs-optional is then enforced by a `fw-contacts --check` pass, not by tokens sitting in the file. *(An earlier reading of this as an ordering problem — intake before create, by analogy with the UAT-15 ops-record finding — was withdrawn: an ops slug encodes the symptom, which isn't known at open time, but a contact slug encodes the name, which is always known first. Creating on the name alone is correct.)*

**Design discussion → FEAT-211.** Adding an advisor across many workspaces raised: (a) `Role:` conflates org **title** with per-engagement **function** (senior dev on one product, architect on another, tester on a third); (b) `—` is a poor delimiter — `;` chosen, comma rejected as it occurs inside names; (c) re-assigning a team to a new workspace is O(N) hand edits at ~50 contacts → batch assign that prompts per-person function. Shorthand/wildcards rejected (a derived set is not a fact — it silently re-scopes people and makes the registry non-auditable); defaulting function from title proposed and withdrawn (varying function per engagement is the normal case). Contacts are unreleased, so no migration.

### Auto-refresh: closing the forgotten-second-step gap (built this session, ships in 0.4.4)

Tester direction: a contact edit should refresh the views with no second step that can be forgotten, **from both ends** — edits made through Claude Code, and edits made outside it (notepad, another editor, a merge), the latter expected to be common. Matches the plugin CLAUDE.md invariant: *"Invariants live in scripts and hooks, not prose. An instruction the AI merely reads is not a guardrail."*

**Inside Claude Code — `PostToolUse` hook.** New `hooks/hooks.json` (matcher `Edit|Write|MultiEdit|NotebookEdit`) + `hooks/refresh-contacts.sh`. Reads the tool payload on stdin, extracts `file_path`, normalises Windows separators, and no-ops unless the path is a record under `workspaces/kb/company/contacts/` (`README.md` excluded). Runs `fw-contacts.sh` from the record's directory so the repo root resolves via `git rev-parse`. Never blocks the edit — a failed refresh reports to stderr. Verified against four payload shapes: escaped Windows path to a contact record (refreshed), unrelated file (silent no-op), contacts `README.md` (no-op), payload with no `file_path` (no-op). All exit 0.

**Outside Claude Code — `fw-contacts.sh --check` + pre-commit.** `--check` copies `workspaces/` to a throwaway mirror, re-invokes the generator against it with `--root`, and diffs the result against the committed views — one implementation of the view format, so the checker cannot drift from the generator. Reports each stale view with a unified diff, plus views that should have been *removed* (assignment gone), and exits 1 with the fix command. New `tools/pre-commit` calls it, gated on the commit actually touching `contacts/*.md` or `*/CONTACTS.md`; `tools/install-git-hooks.sh` installs it per clone (git hooks are not version-controlled), refuses to overwrite a foreign pre-commit, and records the plugin path in `.git/fw-contacts-path` so the hook works without `CLAUDE_PLUGIN_ROOT`.

**End-to-end verification.** Clean tree → `--check` "OK: all CONTACTS.md views match the contact records.", exit 0. Simulated an outside-Claude edit (`sed` on the record, mimicking notepad) → `--check` exit 1 naming `workspaces/widget/CONTACTS.md` with the one-line diff. Installed the hook, staged the record, `git commit` → **blocked**, exit 1, diff shown, "pre-commit: blocked — regenerate the views, stage them, and commit again." Regenerated + re-staged → commit succeeded with "OK: all CONTACTS.md views match…". Test commit rolled back (`git reset --soft HEAD~1` + unstage); repo left at `6b12c4d` with files intact as untracked.

**Also updated:** `commands/fw-contacts.md` step 2 no longer instructs a manual rerun (the hook does it; run by hand only if the hook's output did not appear) and step 3 reports the hook's lines; CHANGELOG entry under Unreleased; version bumped 0.4.3 → 0.4.4 in `plugin.json` and `marketplace.json`.

**Residual gaps (not defects — scope):**
- **CI not wired.** `--check` is ready to drop into a workflow; `framework-uat` has no `.github/`, so none was invented. The local net (hook + pre-commit) is complete without it.
- **The pre-commit hook is per-clone.** Anyone who has not run `tools/install-git-hooks.sh` commits unguarded. CI is the backstop for that, which argues for wiring it.
- **A running session does not pick up the new hook** until Claude Code restarts (same constraint as UAT-29 for skill bodies). Verified only by direct payload invocation this session, not by a live in-session edit — worth a numbered re-test after restart.
- **Betty's `Assigned` line currently reads `widget — technical writer`**, set as the staleness-test fixture rather than by tester decision; left in place pending the FEAT-211 discussion above.
