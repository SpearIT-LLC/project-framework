# Framework Workspace — Authority Boundary

**Inside `workspaces/framework/`, this directory and this file are the sole
authority.** The old framework's structure and docs — `framework/`, `templates/`,
`plugins/`, `tools/`, the root `.claude/` — are out of scope here: never read them
as guidance for this workspace's design. ADR-009 governs; its decisions D1–D5 are
binding.

## What this workspace is

The source tree of the new SpearIT Framework — which IS the plugin
(`spearit-framework-dev`, publishing as `spearit-framework` at graduation). Only
plugin content ships; repo structure (`kanban/`, `history/`, `workspaces/`) is
generated by commands, never packaged.

## Rules

- **One authored source per concept** (Single-Source Rule, ADR-008). Nothing here
  restates the old repo. Carry-ins are *moves*, justified in writing at the time.
- **Invariants live in scripts and hooks, not prose.** An instruction the AI merely
  reads is not a guardrail.
- **`standards/` is staging** (ADR-009 OQ1): files move in via `git mv`, convert to
  skills, and leave in the same commit. One home at all times. It never ships.
- **Work items live on the repo's single board** (`project-hub/work/`) with
  `Workspace: framework` (ADR-009 D5). The generated `kanban/` is a test fixture
  only.
- **Verify against the built plugin**, not this source tree — a guarantee that
  doesn't install hasn't shipped.
