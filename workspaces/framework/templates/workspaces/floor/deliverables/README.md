# deliverables/

A file belongs here **iff it was handed over and accepted.** (Industry line, PMBOK:
a *deliverable* is a work product formally owed to and accepted by the other party;
everything else is a work product and lives where the work lives.)

- **Write-once, at acceptance** — snapshots of exactly what shipped (e.g.
  `v1.2-2026-08-19/`), written by the release/delivery step, never edited by hand.
- Git remains the authority for history; this folder is the browsable copy of
  record, kept for accessibility.
- Test **results** enter only when they are owed (contracted FAT/SAT reports,
  validation evidence). Internal runs never do. Test **definitions** belong with
  `requirements/` — they are the executable form of acceptance criteria.
