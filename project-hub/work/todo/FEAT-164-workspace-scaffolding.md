# Feature: Workspace Scaffolding (`/fw-new-workspace`)

**ID:** FEAT-164

**Workspace:** framework

## Summary

Implement `/fw-new-workspace <name> <type>` so that standing up a workspace is a
command, not an improvisation. The command generates the scaffold for the four
workspace types (ADR-009 OQ5); the command **is** the source of truth for the
structure — no standalone structure document exists that the command does not
generate (ADR-009 validation criteria).

> **Rewritten 2026-08-18** per ADR-009 (was "Scalable Multi-SOW Content Folder
> Structure" under ADR-005, which called for *documenting* a reference layout).
> ADR-009 D3 inverts that: structure is *generated by commands*, and documenting it
> separately would recreate the restatement rot ADR-008 diagnosed. Implemented as
> part of the **framework workspace build**.

## Motivation

The field evidence (ADR-009): Honda's `customers/honda/*` grew by accretion; BD's
folder grew a `src.orig - Copy`. A generated scaffold makes setup repeatable in
minutes and continuously exercises the creation path — the never-executed
`Setup-Framework.ps1` class of rot cannot occur in a command that is used for every
new workspace.

## Scope

**In:**
- **Common floor** (every workspace type): meetings, research/reference,
  deliverables, contacts, SOW/legal home — derived from the Honda/BD common set
  (ADR-009 D4). No source tree required.
- **Four types, differing only in initial scaffolding** (ADR-009 OQ5 — never runtime
  branching):
  - `application` — adds `poc/`, `src/`, `tests/`, dist/publish home. (Library and
    toolkit fold in here.)
  - `knowledgebase` — adds domain/cookbook/faq/reference + index (PARA: Area,
    ongoing).
  - `sow` — adds requirements, reports, deliverables emphasis (PARA: Project, ends).
  - `operations` — adds request/incident intake (PARA: Area, ongoing).
- Each generated workspace gets a README stating name, type, purpose (AI-assisted
  fill-in at creation — this is where the value-add is).
- `/fw-init` counterpart generates the repo spine (`kanban/`, `history/`,
  `workspaces/`, seed `.gitignore` per ADR-009 OQ4) — scoped under FEAT-190; this
  item owns the per-workspace scaffold.

**Out (this item):**
- Workspace-aware reporting (FEAT-163).
- Migration of Honda/BD/Toyota onto the model (their own migration work items, BD
  first per ADR-009 sequencing).
- A mini-swarm interview flow at creation (07-16 idea — possible follow-up; ship
  name/type/description prompts first).

## Acceptance Criteria

- [ ] `/fw-new-workspace <name> <type>` generates the common floor plus the type's
      scaffold for all four types.
- [ ] A document-only workspace (BD shape) stands up with no source tree and nothing
      irrelevant in it.
- [ ] Generated README carries name, type, purpose.
- [ ] No standalone document describes the scaffold; the command doc + the command
      are the one home (script-checkable per TECH-189 pattern).
- [ ] Deterministic parts live in a script; AI assists only where judgment adds value
      (README content), per the script-based execution pattern.

## Notes

- Type names are lowercase singulars: `application`, `knowledgebase`, `sow`,
  `operations`.
- Scaffold contents above are the starting sketch — refine against BD first
  (sketch → use → formalize), since BD cannot be stood up by hand-editing.
